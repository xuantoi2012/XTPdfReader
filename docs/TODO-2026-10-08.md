## 1. Duplicate and Bring to front (done)
- Two icon buttons at the end of the shape bar and the text bar (`ReaderWindow.PropertyActions.cs`). **Duplicate** copies the selection 12 pt down-right (the other way near the right / bottom edge); a group (shape + text boxes) is copied as a new group; the copy is selected; one undo step. **Bring to front** rewrites the selection (a group in its own order) so it ends last in `/Annots`.
- `AnnotationStore.Compute` put a rewritten annotation back at its old index, so on screen the stacking only changed after Save. A spec rewritten from scratch (`ObjectNumber == 0`) now goes to the end at once, exactly where Save puts it; a file annotation that is only moved keeps its place.
- Tests: `TestPropertyActions`, `TestPropertyActionsOnGroup` (`Tests/PropertyBarTests.cs`, which also holds the `RunReaderFlow` helper for the next steps); rendered check `results/property-actions-duplicate.png`.

## 2. Dash style for shapes (done)
- `ShapeStyle` has a fifth field `Dash` (Solid / Dashed / Dotted). It is written only when not solid, so old files and solid shapes keep their exact text and decode as solid.
- Appearance stream (`PdfQuickAnnotationService.AddShape`): `/BS /S /D /D [..]` plus `SetLineDash` (dashed = 4w on / 2.5w off with butt caps; dotted = round dots every 2w). The on-screen layer draws the same appearance, so file and screen match. The arrow head stays solid.
- Live preview (`ShowShapePreview` -> `ApplyDash`) uses the same factors. Property bar: "Line style" combo after the width; the choice is remembered per tool with colour and width, and a selected shape's style is shown in it.
- Test `TestShapeDashStyle` (`Tests/PropertyBarTests.cs`): encode / decode compatibility, bar changes the selected shape, /BS written into a copy the way Save does; rendered check `results/shape-dash.png`.

## 3. Opacity for shapes and text (done)
- `ShapeStyle.Opacity` and `TextFormat.Opacity` (percent, 100 / 75 / 50 / 25). Written only when below 100 (shape: after the dash field, so a shape with opacity always carries its dash), so old files and opaque annotations keep their exact text.
- File: the annotation gets `/CA` and the appearance stream sets an ExtGState with the same fill / stroke alpha (shapes in `AddShape`, text boxes in `AddTypewriter`). Because the on-screen layer shows the same appearance, screen and file match. The shape preview and the in-place text editor fade too.
- Property bar: "Opacity" combo after the line style (shapes) and after the colours (text). Callout text has no opacity (the combo is hidden for callouts); the text-box default remembers the last opacity like the other text settings.
- Test `TestOpacity` (`Tests/PropertyBarTests.cs`); rendered check `results/opacity.png` (25 % and 50 % lines, 75 % text).

## 4. Fill colour for closed shapes (done)
- `ShapeStyle.Fill` (hex, "" = none) for rectangle, cloud and oval; a seventh field, written only when set (then the dash and opacity fields come before it). A line or arrow never keeps a fill. Palette in `ShapeStyle.Fills`: none, white, yellow, red, green, blue, purple, grey (soft tints, so the drawing underneath stays readable; the opacity combo makes them see-through).
- File: the annotation gets `/IC` and the appearance stream fills then strokes. The cloud's bumps are separate half-discs, so the inner rectangle is added to the fill pass and the outline is drawn after it. The shape preview shows the fill too.
- Hit test: the inside of a filled shape is now clickable (an open one still only reacts on its outline). Property bar: "Fill colour" combo after the line style, hidden for arrows and lines.
- A shape whose opacity is not one of 100 / 75 / 50 / 25 (e.g. written by another program) shows 100 % in the bar until changed.
- Test `TestShapeFill` (`Tests/PropertyBarTests.cs`); rendered check `results/shape-fill.png`.

## 5. XT Capture: screen capture as its own always-running program (first version, built)
Owner decisions (2026-10-08): capture is not part of the Reader window. **XT Capture** (`XTCapture/`, `XTCapture.exe`) is a separate small program, built and installed with the Reader, that lives in the tray; it starts with Windows (a setting, on at first run); shortcut Win+C; a half see-through capture button in the bottom right corner of the screen. One capture tool: the Reader's SnapShot tool was removed (it did the same job on the PDF page only); the Reader's Capture and Store buttons start XT Capture. Every capture is kept in XT Capture's **Store**; comments drawn on a capture must stay editable later, and the store is not PDF (PDF is an export option).

- **Projects**: `XTCapture.Core` (overlay, screen grab, region maths, handles, Store, shortcut, settings; no PDF code) and `XTCapture` (WinExe: tray, corner button, Store / preview / settings windows, toast, autostart, command pipe, PDF export with iText loaded only on export). `Services/CaptureLauncher.cs` in the Reader starts it (`XTCapture.exe --capture | --store | --settings | --exit | --background`); a copy that is already running takes the command through the pipe `XTCapture_Command_<user>` and the new start exits. `AppUpdateService` asks it to quit before an update replaces the files. `Build-Release.ps1` publishes both into the same folder: one Velopack package.
- **Overlay** (`CaptureOverlayWindow`): frozen, dimmed screen of all monitors; a white crosshair (with a dark under-line so it shows on light windows) replaces the black cursor; mode bar with icon and text (Window, Rectangle, Circle, Polygon; keys W R E P). Window mode: dashed frame with title and size, Tab or the wheel cycles the windows behind, a covered window is asked to paint itself (`PrintWindow`) and falls back to the frozen pixels. Rectangle / Circle: drag or two clicks. Polygon: click corners, close by clicking the first one, double-click or Enter, Backspace removes the last. **Handles** after a pick (all kinds, also a picked window): eight on a rectangle / circle, one per corner on a polygon, drag inside to move, a click outside starts over; the pointer shows resize arrows. Bar: Copy (Enter), Store, "Outside: white / clear" (circle, polygon).
- **Corner button** (`FloatingCaptureButton`): 48 px, 50 % opaque until the pointer is over it, always on top, never takes focus, not in Alt+Tab; click = capture, drag = move (remembered; falls back to the corner when its place is no longer on a screen), right-click menu (Capture, Store, Settings, Hide this button, Exit). It and the Store are hidden while the screen is frozen.
- **Shortcut** (`HotkeyService`: `RegisterHotKey` on a message-only window, no keyboard hook): Win+C is already taken by Windows (Copilot) on the owner's PC (registration fails with error 1409; Win+Shift+C and Ctrl+Alt+A are taken too). XT Capture then uses the first free one of Win+Alt+C, Ctrl+Alt+C, Ctrl+Shift+C, Ctrl+Alt+F9 and says so in Settings and in the first-run message; Settings lists presets. **Decision needed**: keep Win+Alt+C, or take Win+C for real with a low-level keyboard hook (what PowerToys does for Windows-key shortcuts: it works, but it is heavier and some virus scanners dislike hooks).
- **Store** (`CaptureStore`, `%LOCALAPPDATA%\XTCapture\Store\<capture>\`: `original.png` as taken, `thumb.png` 360 px, `meta.json`; `markup.json` is reserved for the comments of the next step). Store window: pictures, Copy, Save PNG, PDF (one page, 1 px = 0.75 pt), Delete to the Recycle Bin, Clean up older than N days, Open folder, Settings; a click on a picture opens a large preview. Copy puts a bitmap and a PNG (which keeps the clear area) on the clipboard.
- **Settings** (HKCU\Software\XTCapture; the theme and accent are read from the Reader's key so both programs look alike): start with Windows (HKCU Run value with `--background`), corner button on / off, shortcut, clear or white outside the shape.
- **Tests** (`Tests/CaptureTests.cs`, in `--ui-smoke`, 125 checks): region maths and cut-out, handles, Store, shortcut parsing / registration / fallback / message, settings, autostart (a test value name), command pipe and the Reader's launcher, the real screen grab, the overlay driven like a mouse (hover, Tab, covered window, handles, drag, two clicks, circle, polygon), corner button, the tray flow (Copy and Store keep the picture and open the Store). Real process check by hand: `XTCapture.exe --background` put the corner button at the bottom right of the 1920 x 1080 main screen, a second `--store` start opened the Store in the same process, `--exit` ended it. Idle size: about 60 MB private (113 MB working set with the runtime), above the 30-50 MB hoped for; WPF itself costs most of it.
- **Not checked** (needs the owner's machine and a real mouse): a monitor with another DPI (the program is system-DPI aware on purpose, so such a monitor is bitmap-scaled and window frames may be off by that scale; per-monitor DPI needs one overlay per monitor), AutoCAD / Word running as administrator (PrintWindow and focus may be refused), GPU-drawn windows that cover another one, the feel of the overlay with a real mouse, Velopack applying an update while XT Capture runs (the quit request is sent first), and Win+C.
- **Next (the big step)**: drawing and comments on a capture, at capture time (a toolbar beside the picked area) and later from the Store, in XT Capture's own editor, saved as `markup.json` beside the untouched picture (rectangle, circle, arrow, line, pen, text, number markers, mosaic as a re-editable object); the shape and text styles of the Reader (dash, opacity, fill, fonts) reused as data; export to PDF with an option to keep the markup as real PDF annotations. Later: a global override for Win+C, per-monitor DPI, a "source" line, Windows.Graphics.Capture for GPU windows.
