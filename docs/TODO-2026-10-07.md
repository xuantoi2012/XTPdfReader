## 8. Layer toggling fixed on real CAD files + orphan layers (2026-10-07)

- **Real bug found with the QUYEN 2.2 file:** `MuPdfViewportWorker.py` called `pdf_enable_layer(i)` with `i` = position in `get_ocgs()` (the `/OCGs` array order). MuPDF's own layer list has a different order on real files (checked: neither `/OCGs` nor `/D/Order` order), so the wrong layers were switched - this is the "toggle shows no change" report. The worker now probes the mapping once per opened document (bit-by-bit enable + `pdf_is_ocg_hidden`, ~66 ms for 1857 layers), verifies it against `pdf_layer_name`, and falls back to the old order only if the probe cannot be trusted. Result on page 31: 19 of 19 layers change the page (was 0).
- **Orphan layers:** `Services/PdfLayerOrphanService.cs` finds OCGs used by pages (properties, nested forms, `/OC`, OCMD, annotations) but missing from `/OCProperties /OCGs`; the Layers panel shows a banner with "Add them to the layer list" (incremental update, permission and signature checks as for Manage layers; 1.6 s on the 170 MB file, adds an "Unregistered layers" group to `/Order`). Tests: `TestLayerToggleRendersAsync` (5 new checks), `--layer-real <pdf> <page> <n> --register-orphans`.
- Not covered by an automatic test: the MuPDF layer-order mismatch itself (generated fixtures have matching orders); it is covered by the real-file command above. A copy of the file is kept out of the repo.

## 10. Print inbox (2026-10-07)

The Merge screen's temp-shelf chips were hard to work with for printed jobs. Incoming PDFs (named pipe -> `ReceiveIncomingPdfs`) now go to one **Print inbox** window on the Merge canvas: every page of every printed file as a thumbnail, captioned `file name . page`, draggable like any merge window (move / Ctrl = copy, Undo works), movable and resizable in Free layout.
- Never part of Merge all or the merge-order dialog; not written into the session-recovery draft.
- **Persistent** (`Services/PrintInboxStore.cs`, `%LOCALAPPDATA%\XTPdfReader\print-inbox.json`): committed when a PDF arrives, when the user removes a file from the inbox, and when pages were merged into a new PDF. Dragging pages into a draft does not commit, so "Done" (discard draft) returns them to the inbox. Files that no longer exist are skipped on load.
- A path delivered twice (the print agent can redeliver after a crash) is ignored - this closes the duplicate-import gap noted in `VirtualPrinter/README.md`.
- Toolbar button `Inbox (N)` shows/hides it; window minimize/close only hide it; a new arrival brings a hidden inbox back. Double-click a thumbnail = select all pages of that printed file; right-click: select file, View in Reader, Show in folder, Remove from inbox. Delete key removes selected pages from the view (file stays).
- Tests: `TestPrintInbox`, `TestPrintInboxView` (UI smoke 42). Screenshot: `results/print-inbox-view.png`.
- Not done: the temp-shelf strip at the bottom is unchanged; no automatic clean-up of old printed files on disk (owner decision needed: keep forever / delete after merge).

## 11. Merge screen layout (2026-10-07, owner decisions)

- Layouts One/Two/Vertical/Three/Grid/Free replaced by **Columns** (default; up to 3 windows side by side with a fixed width taken from the Merge window's size, 4th onwards scroll sideways) and **Rows** (one window per row = one thumbnail strip, up to 3 rows share the height, more scroll down). 1-2 windows (rows: 1-2) are stretched evenly. The choice is remembered (`AppSettings.MergeLayoutMode`). No free placement, no resize.
- Windows are re-ordered by dragging the title bar onto another window's slot (undoable; the order is the merge order); the layout re-flows at once.
- The **windows** button opens a popup with a tick per window and Select all / Deselect all. Only ticked windows are shown and **only ticked windows go into "Merge into one file"** (the print inbox never does). Unticked windows stay in the draft.
- The **Done** button is gone (it only hid the window, same as the title-bar close).
- An empty Temp shelf strip shrinks to 64 px so three rows fit the default 800 px Merge window; at larger Page size a row needs more height and fewer than 3 rows fit.
- Printed files are kept forever; merging only takes their pages out of the inbox. A "clean up printed files" button comes later, and the print agent should write into an app-defined folder (e.g. under `%LOCALAPPDATA%\XTPdfReader\Printed`) instead of Temp.
