## 3. Virtual printer (next feature)

Already there: named pipe `XTPdfMergeApp_IncomingPdfPipe` (one absolute PDF path per line) feeding the Merge shelf; AutoCAD keeps its own plot engine and sends the finished PDF path through the same pipe (`docs`: `Tests/GpuPdfium/INCOMING-MERGE-SHELF-2026-10-06.md`). The virtual printer is for Word, Excel and browsers.

Options, in the order to try:
1. **IPP printer inside the app** (minimal IPP server on localhost, `Add-Printer` with the Microsoft IPP Class Driver). Spike: print from Notepad, Word, Chrome and look at the document format received. PDF = done; raster = not good enough.
2. **Windows 11 Print Support virtual printer** (Microsoft Virtual Print Class Driver is already on the dev machine). Needs package identity (MSIX / sparse package); Windows 11 only.
3. **PostScript printer with a pipe port** (the PDF24 way) + a PS-to-PDF converter (Ghostscript is also AGPL; fine for internal use).
4. Own V4 driver: last resort (WDK, signing).

Questions still open: number of machines and Windows versions; vector required for Office/browser output or is 600 dpi raster enough; admin rights available for the one-time printer install.

## 5. How to run the tests now (2026-10-07)

`Tests\Run.ps1 [-MuPdfSample <any multi-page PDF>]` runs two passes: **A** the engine-specific PDFium suite built with `-p:MuPdfOnly=false` (512 checks), **B** the production MuPDF-only build:
`--layer-merge-only` (80), `--ui-smoke` (29, PNGs in `results\ui-*.png`) and, when a sample PDF is given, `--mupdf-viewport-check` (27) and `--mupdf-throughput-viewer-check`.
The stale checks were fixed by making them engine-aware (4608 px cap and "all pages / layers / documents go to MuPDF" in the production build; one failed file no longer disables MuPDF) and by pinning the Memory-saving profile for the suite (the default Balance tier prefetches more and varies per machine).
`--layer-real <pdf> <page> <maxLayers>` hides layers one by one on a real file and says which ones change the page (a quick check of the "toggle shows no change" report on a real drawing).
