## Digital signature (Ký số), one signer, Vietnamese administrative style
- `Services/PdfDigitalSignService.cs`: PAdES (iText 9, CADES detached, incremental update so earlier signatures stay valid). The private key is never read: the hash goes to the key through Windows (CNG/CSP), so a Viettel-CA USB token works once its middleware has put the certificate in the Windows store (CurrentUser/LocalMachine My). `.pfx` is accepted for tests. SHA-256, RSA or ECDSA.
- Look: seal image on the left, on the right organisation (upper case), "Ký bởi", "Ký ngày"; Arial from Windows fonts (Vietnamese).
- Optional TSA URL (RFC 3161) and OCSP/CRL embedding. NO default TSA URL: the Viettel-CA address was not found, ask the provider.
- `Controls/SignPdfWindow.cs` (pick certificate, draw the box on a page, seal, reason, TSA), `ReaderWindow.Sign.cs` (ribbon "Sign" and "Check Signatures"). Output is always a new file `_signed.pdf`.
- Tests: `PerformanceTests.exe --sign-check` (6 checks, self-signed cert). NOT tested: a real token, the TSA, OCSP.
- Settings (registry): SignOrganization, SignSealImage, SignTsaUrl, SignThumbprint, SignLocation, SignEmbedRevocation.

## Round 5: a big PDF on a network drive opened as an empty tab
- Cause (reproduced with `P:\...\03. QUYEN 2.2 ... .pdf`, 162 MB, 277 pages): the MuPDF worker read the file over the share with many small random reads. The "metadata" request (sizes of all pages) took 35 s with a warm cache, over the 30 s command limit in `ExperimentalMuPdfViewport.CommandAsync`; the worker was killed, the open was counted as a damaged file, and the tab stayed blank with no message. Measured: raw read of the file 59 s (2.7 MB/s that day), `open` 7 s + sizes 27 s in MuPDF.
- Fix: `Services/RemoteFileStage.cs` copies a network file once (sequentially) to `%TEMP%\PDFReaderPro\remote\` and the worker reads the copy (`CommandAsync`, `RenderAsync`, close/memory requests). The progress shows as "Opening file x %" (`PdfFileBuffer.GetLoadedFraction` falls back to it). Copy name = hash of path + length + mtime, so a changed file is copied again; copies older than 2 days are deleted; falls back to the old direct read when there is no room. After the copy: metadata 0.3 s (`--remote-open <file>`: copy 15 s warm).
- A failed open now also shows a message (`DocumentSession.FinishOpeningGroup`).
- Known limit: saving to the network file changes its time, so the next read copies it again.
